# Documentation Layout

Where a new page goes, and why the tree is cut this way. The split follows [Diátaxis](https://diataxis.fr): 4 kinds of
page, each answering a different question, never mixed on 1 page

| Kind | Question | Lives in |
|---|---|---|
| Tutorial | How do I get my first change landed? | `docs/contributing/tutorial/` |
| How-To | How do I do this 1 task? | `docs/contributing/howto/` |
| Reference | What exactly does the SDK do? | docstrings, rendered into `docs/api-references/` |
| Explanation | Why is it like this? | `docs/contributing/explanation/` |

Explanation may motivate a rule and link to it, never restate it: 2 copies drift, and the copy a reader finds first wins

## Audience

| Path | For |
|---|---|
| `README.md` | SDK users: install and usage |
| `docs/api-references/` | SDK users; generated by `scripts/generate-api-docs.py`, never edited by hand |
| `docs/contributing/` | People and AI agents changing this repository |
| `AGENTS.md` | AI agents: invariants, layout and the index of `docs/contributing/` |
| `.agents/skills/` | AI agents: when to act and what to report, linking the how-tos |

[style.md](../howto/docs/style.md) applies to all of them

## Adding a Page

1. Pick the kind from the table above; split a page that answers 2 questions
2. Add a 1-line entry to [howto/README.md](../howto/README.md) for a how-to, and to the index in `AGENTS.md` for any page
